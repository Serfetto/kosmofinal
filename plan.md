## 0. Главное

1. **Главный разрыв — единица концентрации.** Сейчас мы считаем «концентрацию» как эквивалентную площадь покрытия в м²/км² ([aggregate.py:183](pipeline/aggregate.py#L183)). Кейс требует шт./км² для заявленного размерного класса. В критерии Т3 прямо сказано: «индекс или площадь маски не заменяют концентрацию». Количественную часть придётся построить заново, а м²/км² оставить только как вспомогательный показатель.
2. **Полевые данные в решении пока не используются.** Нужны отбор строк в коде по конфигу, реестр включённых и исключённых строк с причинами, реестр пар «событие ↔ снимок» и разбиение с учётом групп. На это приходятся критерии Т1 (10), Т4 (7) и заметная часть О1 (15).
3. **Совместно откалибровать «снимок → шт./км²» не получится,** и это видно по данным. У S2 (апрель 2015) и S1 (открытый Тихий океан) нет ни одной сцены Sentinel-2. У S3 такие сцены есть только для 3 событий 2016 года. У S4 (Чёрное море, июнь 2024) сцена в пределах ±1 сут. есть у 32 из 33 событий, но время наблюдения, длина полосы и N/A не указаны, а метка описывает весь мусор. Постановка допускает раздельную проверку, поэтому строим так: **детектор проверяем на MARIDA, модель концентрации — на полевых данных, перенос на снимки проверяем отдельным экспериментом на парах S4.** Если перенос не подтвердится, показываем статус «исследовательская оценка».
4. **Целевая величина (предлагаю зафиксировать):** основной профиль **A — плавающий макропластик ≳2 см, визуальный учёт** (S2, 63 события, N/A воспроизводится точно). Региональный профиль **B — весь плавающий макромусор ≳2–2,5 см** (S4 для Чёрного моря и S3 для проверки переноса). На карте профиль B подписан как «не только пластик».
5. **Детектор оставляем,** но добавляем: бинарные метрики P/R/F1/IoU, базовый алгоритм с порогом по FDI на той же выборке, разбор ложных срабатываний по классам сложного фона, сохранённые предсказания, зоны-полигоны и отдельную маску качества.
6. **Веб-карта:** основная единица — шт./км²; для каждого значения показываем профиль, интервал и один из четырёх статусов. Добавляем слой полевых наблюдений, визуально отличимый от модельных оценок, маску качества, выгрузку GeoJSON и CSV и повтор сохранённого запроса.
7. **Воспроизводимость:** конфиги, одна команда на каждый шаг, тесты на контрольных примерах и на утечки, веса моделей в репозитории, закреплённые версии зависимостей.
8. **Дрейф, маршрут и тренды** относятся к дополнительным функциям (О6, 5 баллов). Их нужно визуально отделить от наблюдений и проверить без использования будущих данных. Приоритет у обязательной части: на неё приходится 100 баллов из 105.

### 2.5. Физический масштаб: почему пиксель не равен полосе

Возьмём даже 1000 шт./км² при площади предмета около 0,01 м². Суммарно это ~10 м² на км², то есть десятая часть одного пикселя 10×10 м на целый квадратный километр. Наш детектор уверенно видит скопления, которые закрывают ≳20–30% пикселя. Значит, **рассеянный мусор из полевых учётов со спутника не виден;** видны только плотные полосы и скопления, сбитые ветром и течениями в линии. Из этого следуют два вывода:
- зоны детекции означают «вероятные скопления», а не «концентрацию в шт./км²»;
- число в шт./км² в сервисе даёт модель, обученная на полевых данных, а спутник подсказывает, где искать. Любую связь «площадь маски → число предметов» можно показывать только как сценарий со статусом «исследовательская оценка».

### 3.3. Формулы (проверяются тестами)

- Измерение: **C = N / A**, где A = `sampled_area_km2`, а для контроля A ≈ L[км] × W[м] / 1000. Для S2 используется авторская площадь.
- ДИ измерения (Гарвуд): `[χ²(α/2; 2N)/2, χ²(1−α/2; 2N+2)/2] / A`.
- Контрольные примеры из постановки: 12 предметов на 0,20 км² → 60 шт./км²; модель дала 75 → абсолютная ошибка 15.
- Контроль по реальным строкам: S2 T1 — 4 / 0,1968 = 20,33 шт./км²; S2 T4 — 7 / 0,24465 = 28,61.
- Площадь покрытия (м²/км²) и доля пикселей маски — вспомогательные показатели, в концентрацию не переводятся.

### 3.4. Измерение и оценка: как не перепутать

| Тип | Откуда | Как выглядит на карте | Поле `value_type` |
|---|---|---|---|
| Измерение | полевое событие, C = N/A | сплошная полоса или кружок с белой обводкой | `measurement` |
| Модельная оценка | модель профиля в проверенной области | заливка гекса или зоны | `model_estimate` |
| Исследовательская оценка | модель вне проверенной области или сценарий | штриховка и значок «иссл.» | `research_estimate` |
| Нет оценки | профиль не применим | серый цвет, «концентрация недоступна» | `unavailable` |

  - ветер ERA5 10 м: среднее за 24 ч до момента (Open-Meteo archive, кеш `data/cache/era5/`);
  - месяц и сезон, бассейн (полигон из конфига);
  - опционально: расстояние до устьев крупных рек (список в конфиге) и фактор схождения течений из `drift.accumulation`, если данные течений доступны на дату.
- [ ] **Базовые алгоритмы** (на той же выборке): медиана обучающей части профиля; простой пространственный прогноз (IDW или kNN по обучающим событиям).
- [ ] **Основная модель** — интерпретируемая, коэффициенты показываются в панели «Метод»:
  - профиль A (N и A известны): отрицательно-биномиальная GLM со смещением `log(A)` (statsmodels) и 2–4 признаками;
  - профиль B (у S4 нет N): лог-линейная регрессия `log C` с регуляризацией;
  - если на CV модель не обходит базовый алгоритм, честно выбираем пространственный базовый и записываем это в отчёт.
- [ ] **Интервалы:** сплит-конформные интервалы по остаткам в лог-шкале на групповой CV (80% и 95%) с проверкой покрытия на отложенной выборке. Для измерений — ДИ Гарвуда (§3.3).
- [ ] **Спутниковая связка (эксперимент, P1):** на принятых парах S4 и S3 проверить, улучшают ли признаки детектора из §5.3 MAE сверх ковариат. Также посчитать ранговую корреляцию «доля детекций в следе ↔ полевая C». Если улучшения нет, фиксируем: «перенос численной оценки на снимки не подтверждён». Спутник тогда используется только для зон, а в числах — только модель по полевым данным со статусом «исследовательская оценка».
- [ ] **Сценарный пересчёт площади в число предметов (P2, опционально):** `N_zone ≈ cover_m2 × ρ` при сценариях ρ (плотность предметов в скоплении, шт./м²: низкая, средняя, высокая) с явными допущениями. Всегда со статусом «исследовательская оценка» и никогда не как основное число.
- [ ] Сохранение: `data/models/conc_<profile>.json` (признаки, коэффициенты, скейлер, конформные квантили, ID обучающих событий, хеш конфига, версия) и `data/eval/concentration/<profile>/predictions.csv` (event_id, fold, y_true, y_pred_main, y_pred_baseline, lo, hi).

### 5.6. Статусы и область применимости (P0, О2 / О4)

**Статус детекции** (по зоне, гексу и дате):

| Статус | Условие (пороги в `detector.yaml`) |
|---|---|
| **обнаружено** | ≥ 2 связанных пикселя, прошедших все фильтры; `valid_frac` гекса ≥ 0,5; сцена не штормовая |
| **не обнаружено** | `valid_frac` ≥ 0,5, детекций нет, сцена спокойная (ветер < 8 м/с, льда нет) |
| **недостаточно данных** | `valid_frac` < 0,5 (облака, блик, лёд) **или** шторм (`wind_max` ≥ 8 м/с) **или** лёд > 0,5%: отсутствие подтвердить нельзя |

**Статус концентрации** (по профилю):

| Статус | Условие |
|---|---|
| модельная оценка | точка внутри бассейна профиля и в пределах проверенной области: расстояние в пространстве признаков до обучающих событий ≤ 95-го перцентиля обучающих kNN-расстояний, месяц и ветер в пределах обучающих диапазонов |
| **исследовательская оценка** | бассейн тот же, но проверенная область не покрыта: например, побережье РФ для профиля B, где нет ни одного полевого события S4. Или используется сценарный пересчёт. Список допущений выводится рядом |
| концентрация недоступна | профиль не применим: пресные воды (Куйбышевское водохранилище, Волгоград), другие бассейны (Невская губа, Амурский залив), профиль A вне Атлантики |

## 7. Сценарий демонстрации на защите

1. **Снимок → качество → зоны.** Сочи или Новороссийск, спокойная дата: исходный снимок, маска качества (облака, блик, суша), зоны со статусом «обнаружено», карточка зоны: площадь, покрытие и отдельно концентрация профиля B со статусом «исследовательская оценка» и допущениями.
2. **Полевые данные → концентрация → отложенная проверка.** Акватория S4 (например, Батуми–Поти, 05.06.2024, T18/T19, сцена в тот же день, облачность ~1%): полоса измерения, C с ДИ, предсказание модели для этого события в режиме отложенной выборки, ошибка, выгрузка CSV.
3. **Сложный случай.** Шторм (статус «недостаточно данных»: барашки неотличимы от мусора), пена или водоросли из разбора ложных срабатываний, либо Керчь с мазутом: что детектор видит и почему это не мусор.
4. **Перепроверка экспертом.** Эксперт называет событие или точку → `/api/field/{event_id}` или `explain`, пересчёт на глазах; «Повторить сохранённый запрос» → sha256 совпадает.
5. **Дополнительно (О6).** Прогноз дрейфа с проверкой на следующем снимке и маршрут «куда ехать, чтобы сильнее всего снизить неопределённость».

## 9. Риски и решения за командой

| Вопрос | Рекомендация | Почему |
|---|---|---|
| Какую величину заявить основной? | **A (пластик ≳2 см, визуальный учёт)**; B — региональный профиль для Чёрного моря, везде подписан «весь мусор» | кейс про макропластик, а у A самые чистые метки (N/A сходится точно). Но только B есть в нашем море, поэтому нужны оба профиля с явным разделением |
| Что делать с Куйбышевом, Волгоградом, Невой, Владивостоком? | оставить, но концентрация «недоступна: вне области применения»; детекции показывать | кейс про морские акватории, а полевых данных для этих мест нет |
| Если перенос на снимки не подтвердится | так и написать; число даёт полевая модель со статусом «исследовательская оценка» | постановка это прямо допускает; критерий О2 вознаграждает честные границы |
| Время на PANGAEA-расширение (S3 только пластик) | только если задачи 1–10 закрыты | даёт тест переноса между регионами, но есть риск, что материал объектов не определить |
| Landsat | только учёт в реестре (`SENSOR_UNSUPPORTED`) | нет красного края, детектор обучен на полосах Sentinel-2 |
| Интерполяция каналов 20 м | сверить с MARIDA; если там билинейная, оставить её и объяснить | важнее совпадение с обучающими данными, чем формальная «чистота» |
| Размер репозитория | проверить `du` после добавления `data/eval` и весов | больше 2 ГБ → в GitVerse только README со ссылкой |

## Приложение Б. Коды причин

| Код | Когда |
|---|---|
| `NOT_TARGET_PROFILE` | строка не входит ни в один профиль (см. §3.2) |
| `NO_SCENE` | в окне поиска нет сцен |
| `SENSOR_UNSUPPORTED` | сцена есть, но детектор к сенсору не применим (Landsat) |
| `INSUFFICIENT_COVERAGE` | данными сцены покрыто меньше 90% следа с буфером |
| `UNUSABLE_PIXELS` | чистая вода по SCL < 50% следа |
| `GLINT` | блик выше порога |
| `UNRELIABLE_SYNC` | ярус C или дрейфовый буфер больше предела в конфиге |
| `GEOMETRY_POINT_ONLY` | предупреждение: известна только середина полосы (S4) |
| `DUPLICATE_BETTER_SCENE` | есть сцена с меньшим сдвигом или облачностью |
| `ACCEPTED` / `ACCEPTED_UNCERTAIN_TIME` | принято (ярус A) / принято только для исследования (ярус B) |
