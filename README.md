# AquaFlow – мониторинг океанического пластика

Веб-сервис для специалиста по экологическому мониторингу. Пользователь выбирает акваторию и дату снимка Sentinel-2
и видит на карте:

- **зоны вероятного скопления** плавающего мусора (детектор по снимку) и маску качества снимка;
- **полевые измерения** из реестра кейса: C = N / A по полосе учёта с интервалом;
- **модельную концентрацию в шт./км²** для заявленного профиля с интервалом, статусом и причинами статуса.

Все результаты выгружаются в GeoJSON и CSV, а сохранённый запрос можно повторить и сверить по sha256.
Кнопка «Скачать отчёт · PDF» собирает отчёт на выбранную дату: обзорная карта с районами скопления, фрагменты
снимка по районам и таблица крупнейших зон с координатами, ориентиром и расстоянием до берега
(`GET /api/report?aoi=&date=&profile=`).

Краткий отчёт с результатами и разбором ошибок — [docs/report.md](docs/report.md).
План интеграции данных кейса — [plan.md](plan.md). Сводка метрик — [data/eval/summary.md](data/eval/summary.md).

| | Типичное решение | AquaFlow |
|---|---|---|
| Что на выходе | маска «мусор / нет» | **концентрация**: м² мусора на км² (доля покрытия пикселя) |
| Сравнение участков | — | гексы H3 одинаковой площади, рисование двух участков, вердикт |
| Время | один снимок | ряд 30 дат: устойчивость зон, тренд |
| Прогноз | — | лагранжев ансамбль: течения SMOC + ветер ERA5, выброс на берег |
| Действие | — | маршрут судна по целям с поправкой на дрейф к моменту прибытия, GPX |
| Ложные срабатывания | как повезёт | CFAR, маска постоянных объектов, фильтр пены, учёт ветра (шторм) |

| Профиль | Что считаем | Размер | Метод | Данные | Где применимо |
|---|---|---|---|---|---|
| **A** (основной) | плавающий макропластик, включая пенопласт | ≳2 см (порог метода) | судовой визуальный учёт, полоса 10 м | S2 Саргассово море, 63 события, N/A известны | СЗ Атлантика (субтропики) |
| **B** (региональный) | весь плавающий макромусор, **не только пластик** | ≳2,5 см | визуальный учёт | S4 Чёрное море (DOORS 2024), 33 события; S3 — только проверка переноса | Чёрное море |

Отдельные предметы, категории, общий мусор и суммарный пластик — разные совокупности, их не смешиваем.
Правила отбора лежат в [configs/profiles.yaml](configs/profiles.yaml), решение по каждой из 935 строк — в
`data/field/selection.csv`.

Три величины на карте различаются и по обозначению, и по смыслу:

| Величина | Откуда | Обозначение |
|---|---|---|
| Полевое измерение | C = N / A по полосе учёта; 95% ДИ по Гарвуду | сплошная полоса или кружок с белой обводкой |
| Модельная оценка, шт./км² | модель профиля по полевым данным | заливка гекса; штриховка — «исследовательская оценка» |
| Зона детекции | детектор по снимку: площадь зоны и покрытие, м² | красный полигон; в шт./км² **не переводится** |

Статусы: детекция — «обнаружено», «не обнаружено» (только при ≥50% видимой воды и спокойном море) и
«недостаточно данных». Концентрация — «модельная оценка», «исследовательская оценка» (перенос не подтверждён:
дальше 60 км от полевых измерений, другой сезон или признаки вне диапазона обучения) и «концентрация недоступна»
(другой бассейн или пресные воды).

## Быстрый запуск на готовых данных

Результаты обработки всех акваторий, полевой реестр, реестр пар, разбиения, веса и метрики лежат в репозитории.
Скачивать снимки и обучать модели не нужно. Требования: Python 3.12, Node 20+, интернет — течения и ветер для
прогноза дрейфа загружаются из Open-Meteo.

```bash
git clone <url репозитория> && cd kosmofinal
python -m pip install uv
python -m uv venv --python 3.12 .venv
python -m uv pip install --python .venv/Scripts/python.exe -r requirements.lock   # Linux/macOS: .venv/bin/python
cd frontend && npm install && npm run build && cd ..
.venv/Scripts/python -m uvicorn backend.app:app --port 8000                        # Linux/macOS: .venv/bin/python
# http://localhost:8000
```

Пример сохранённого запроса лежит в `data/queries/0a0b3aaaf8f9.json`: зоны «Батуми — Кобулети» на 05.06.2024,
профиль B, GeoJSON. Повтор: `curl -X POST http://localhost:8000/api/queries/0a0b3aaaf8f9/rerun` — поле `match`
сравнивает sha256 результата с сохранённым. В интерфейсе:
`http://localhost:8000/?aoi=batumi&date=2024-06-05&profile=B&mode=conc&q=0a0b3aaaf8f9` → кнопка «Повторить».

На Windows с кириллицей в консоли: `set PYTHONIOENCODING=utf-8`.

## Воспроизведение результатов

Все параметры заданы в конфигах [configs/](configs/): профили и отбор, реестр пар, модель концентрации и
разбиение, пороги детектора.

```bash
# Всё, кроме пересборки карт (~5 мин; MARIDA нужна для шага детектора)
.venv/Scripts/python -m pipeline.reproduce            # --offline — реестр пар из кеша, без сети

# или по шагам
.venv/Scripts/python -m pipeline.field prepare        # отбор 935 строк → data/field/
.venv/Scripts/python -m pipeline.pairs build          # реестр «событие ↔ снимок» → data/registry/pairs.csv
.venv/Scripts/python -m pipeline.pairs detect         # признаки детектора по следу принятых пар (скачивает фрагменты)
.venv/Scripts/python -m pipeline.splits build         # группы и отложенная выборка → data/splits/
.venv/Scripts/python -m pipeline.concentration evaluate   # CV, отложенная выборка, перенос → data/eval/concentration/
.venv/Scripts/python -m pipeline.eval_detector        # MARIDA test: базовые и основной → data/eval/detector/
.venv/Scripts/python -m pipeline.eval_detector_lro    # детектор на регионе, исключённом из обучения (~10 мин, GPU)
.venv/Scripts/python -m pipeline.pairs transfer       # перенос «детекции в следе ↔ полевая концентрация»
.venv/Scripts/python -m pipeline.drift_check          # прогноз дрейфа на парах соседних снимков
.venv/Scripts/python -m pipeline.review sample        # набор фрагментов для ручной разметки детекций; review score — итог
.venv/Scripts/python -m pytest -q                     # контрольные примеры, утечки, API

# Проверка конкретного расчёта без изменения кода
.venv/Scripts/python -m pipeline.field explain S2:MSM41_litter-T4
.venv/Scripts/python -m pipeline.concentration explain B 39.72 43.55 2025-07-18T08:10
```

Полный пересчёт снимков и детектора:

```bash
# 1. обучение детектора (MARIDA: https://zenodo.org/records/5151941 → распаковать в data/raw/marida)
.venv/Scripts/python -m pipeline.train
# 2. снимки → детекция → карты всех акваторий (скачивание ~17 ГБ, детекция ~45 мин на GPU)
.venv/Scripts/python -m pipeline.build run
```

Новая акватория:

```bash
.venv/Scripts/python -m pipeline.build add azov "Таганрогский залив" 38.6 46.9 39.3 47.3 --port 38.93,47.2 --tz 3
.venv/Scripts/python -m pipeline.build run azov
```

**Ресурсы.** Сервис на готовых данных: 1 ГБ RAM. Шаги `reproduce`: 4 ГБ RAM, несколько минут на CPU. Проверка
детектора на MARIDA: около 5 минут; GPU с CUDA ускоряет XGBoost, но не обязателен. Полный пересчёт снимков:
16 ГБ RAM, ~20 ГБ диска.

**Ключи** не нужны: Planetary Computer, Open-Meteo, PANGAEA и Zenodo открыты.

| `data/eval/detector/` | метрики, сохранённые предсказания на MARIDA test, разбор ошибок, галерея FP/FN, проверка на исключённом регионе |
| `data/eval/transfer.json`, `drift_check.json` | эксперимент переноса на снимки; проверка прогноза дрейфа |
| `data/eval/review/` | фрагменты детекций и контрольных точек для ручной разметки (`review.csv`, `sheet_*.png`) |
| `data/models/` | `xgb.joblib` (детектор), `conc_A.json`, `conc_B.json` (модели концентрации) |
| `data/web/<aoi>/` | карты для сервиса: гексы, ряды, зоны, маска качества, оценки концентрации |

## Архитектура

```
Полевой CSV ──► field.py (отбор по профилям, геометрия, время, C = N/A) ──► splits.py (группы, отложенная выборка)
      │                                                                          │
      └──► pairs.py ◄── STAC Planetary Computer + ERA5 (реестр пар, качество)   ▼
                                                     concentration.py (медиана, IDW, GLM; интервалы; применимость)
Sentinel-2 L2A ──► s2.py ──► features.py (нормализация фона) ──► XGBoost (MARIDA) + фильтры ──► detect.py
                                                                                   │
                        aggregate.py: зоны, маска качества, статусы, гексы H3, оценки концентрации
                                                                                   │
       Open-Meteo: течения SMOC, ветер ERA5 ──► drift.py / route.py (прогноз — дополнительная функция)
                                                                                   │
                         backend (FastAPI) ──► frontend (React, MapLibre, Chart.js)
```

## API

| Метод | Что возвращает |
|---|---|
| `GET /api/aois` | акватории, даты, бассейн, применимость профилей |
| `GET /api/profiles` | профили: материал, размер, метод, версия модели, MAE на отложенной выборке |
| `GET /api/field?profile=&bbox=&date_from=&date_to=` | полевые измерения (GeoJSON) |
| `GET /api/field/{event_id}` | расшифровка расчёта: строки реестра, формула, ДИ, пары со снимками |
| `GET /api/field/objects` | отдельные предметы (контекст, не метки) |
| `GET /api/aois/{aoi}/{date}/zones` | зоны детекции с площадью, покрытием, концентрацией по профилям и статусами |
| `GET /api/aois/{aoi}/concentration?profile=` | концентрация по гексам и датам: значение, 80%-интервал, статус |
| `GET /api/aois/{aoi}/{date}/hex/{i}?profile=` | оценка в гексе с признаками и причинами статуса |
| `GET /api/aois/{aoi}/hexes`, `/series` | гексы H3; покрытие, статусы и качество по датам |
| `GET /api/export?aoi=&date=&profile=&layer=zones\|hexes&format=geojson\|csv` | выгрузка (заголовок `X-Result-SHA256`) |
| `POST /api/queries`, `GET /api/queries/{id}`, `POST /api/queries/{id}/rerun` | сохранённый запрос и его повтор |
| `GET /api/pairs?format=json\|csv` | реестр пар |
| `GET /api/metrics` | детектор, концентрация, пары, таблица «что где проверено» |
| `GET /api/aois/{aoi}/{date}/drift`, `drift_point`, `accumulation`, `route` | прогноз дрейфа, зоны схождения, маршрут (доп. функции) |

## Ограничения

- При 10 м видны скопления и полосы мусора (от ~20–30% пикселя), а не отдельные предметы. Рассеянный мусор из
  полевых учётов (десятки–сотни шт./км²) со спутника не виден, поэтому концентрация в шт./км² берётся из модели по
  полевым данным, а не из площади маски.
- Для побережья РФ полевых измерений нет: там профиль B даёт исследовательскую оценку, профиль A недоступен.
  Для пресных водоёмов (Куйбышевское водохранилище, Волгоград) и других морей концентрация недоступна.
- Пластик, плавник и водоросли спектрально разделяются не полностью; подтверждение — судно или дрон.
- Детектор обучен на MARIDA (в основном тропики); нормализация фона снижает сдвиг доменов, но не убирает его.
- Течения SMOC (1/12°) не разрешают мелкие бухты; для водохранилищ — только ветровой дрейф.
