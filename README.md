# AquaFlow — мониторинг плавающего мусора по снимкам Sentinel-2

AquaFlow — веб-сервис для специалиста по экологическому мониторингу. Пользователь выбирает акваторию и дату снимка
и получает на карте:

- **зоны вероятного скопления** плавающего мусора, найденные детектором на снимке Sentinel-2, и маску качества
  снимка (облака, блик, шторм, суша);
- **полевые измерения** из реестра кейса: концентрация C = N / A по полосе учёта с 95% доверительным интервалом;
- **модельную концентрацию в шт./км²** по гексам H3 с интервалом, статусом доверия и причинами этого статуса.

Дополнительно сервис строит прогноз дрейфа на 72 ч (течения и ветер) и маршрут судна к скоплениям, собирает PDF-отчёт
на выбранную дату и выгружает результаты в GeoJSON и CSV. Сохранённый запрос можно повторить и сверить результат
по sha256.

## Кратко о решении

Главная идея: **спутник и полевые данные отвечают на разные вопросы**, и мы их не смешиваем.

- **Снимок показывает, где искать.** При разрешении 10 м видны плотные скопления и полосы мусора, но не рассеянный
  мусор: даже 1000 предметов на км² по 0,01 м² дают ~10 м² на км², то есть десятую часть одного пикселя. Поэтому
  детектор находит зоны скопления, а их площадь в шт./км² не переводится.
- **Полевые данные дают количество.** Концентрация в шт./км² считается моделью, обученной на полевых учётах. Модель
  сама сообщает, где ей можно верить: рядом с измерениями это «модельная оценка», вдали от них
  «исследовательская оценка», в другом бассейне «концентрация недоступна».

На карте это три разные величины с разными обозначениями:

| Величина | Откуда | Как показана |
|---|---|---|
| Зона детекции | детектор по снимку: площадь зоны и покрытие, м² | красный полигон |
| Полевое измерение | C = N / A по полосе учёта, 95% ДИ по Гарвуду | полоса или кружок с белой обводкой |
| Модельная оценка, шт./км² | модель профиля по полевым данным | заливка гекса; штриховка — исследовательская оценка |

Концентрация считается для двух **профилей**. Профиль фиксирует, что именно измеряется, потому что пластик ≳2 см
и весь мусор ≳2,5 см — разные величины:

| Профиль | Что считаем | Обучен на | Где применим |
|---|---|---|---|
| **A** | плавающий пластик ≳2 см | S2, Саргассово море, 63 события | северо-западная Атлантика (субтропики) |
| **B** | весь плавающий мусор ≳2,5 см, не только пластик | S4, Чёрное море (DOORS 2024), 33 события | Чёрное море |

В сервисе 18 акваторий: Сочи — Адлер, Новороссийск, Керченский пролив — Анапа, Невская губа, Владивосток,
Куйбышевское водохранилище, Волгоград, Батуми — Кобулети, а также районы полевых данных кейса в Чёрном и Северном
морях. Правила отбора полевых данных — [configs/profiles.yaml](configs/profiles.yaml), решение по каждой из 935 строк
реестра — `data/field/selection.csv`.

## Быстрый старт

Готовые результаты обработки всех акваторий, модели и метрики лежат в репозитории, поэтому **скачивать снимки
и обучать модели для запуска не нужно**. Сервису нужен интернет: течения и ветер для прогноза дрейфа приходят
из Open-Meteo, просмотр сцен и слой классов модели — из Microsoft Planetary Computer.

### Вариант 1: Docker (проще всего)

```bash
git clone <url репозитория> && cd kosmofinal
cp .env.example .env        # необязательно, см. раздел про .env
docker compose up -d --build
```

Сервис откроется на http://localhost:8000, проверка: `curl http://localhost:8000/api/health`.

Фронтенд собирается внутри образа. Кеш (течения и ветер, зоны скопления, сохранённые запросы) хранится в томе
`aquaflow-cache`, поэтому переживает пересборку. Сбросить его можно командой `docker compose down -v`.

Без compose: `docker build -t aquaflow . && docker run -d -p 8000:8000 --env-file .env -v aquaflow-cache:/app/cache aquaflow`
(если `.env` не создавали, уберите `--env-file .env`).

### Вариант 2: локально

Нужны Python 3.12 и Node.js 20+.

```bash
git clone <url репозитория> && cd kosmofinal

# Python-окружение с точными версиями, на которых получены метрики
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.lock

# Сборка фронтенда: бэкенд раздаёт его из frontend/dist
cd frontend && npm ci && npm run build && cd ..

# Запуск
python -m uvicorn backend.app:app --port 8000
```

Откройте http://localhost:8000. Документация API: http://localhost:8000/api/docs (Swagger) и `/api/redoc`.

- **Разработка фронтенда:** `cd frontend && npm run dev` поднимет Vite на http://localhost:5173, запросы к `/api`
  проксируются на бэкенд (порт 8000).
- **На сервере** добавьте `--host 0.0.0.0`, иначе сервис слушает только localhost. Каталог `data/` должен быть
  доступен на запись, иначе задайте отдельный каталог кеша в `AQUAFLOW_CACHE`.
- **Windows с кириллицей в консоли:** `$env:PYTHONIOENCODING="utf-8"` (PowerShell) или `set PYTHONIOENCODING=utf-8` (cmd).

Пример сохранённого запроса: зоны «Батуми — Кобулети» на 05.06.2024, профиль B. Откройте
http://localhost:8000/?aoi=batumi&date=2024-06-05&profile=B&mode=conc&q=0a0b3aaaf8f9 и нажмите «Повторить» или
выполните `curl -X POST http://localhost:8000/api/queries/0a0b3aaaf8f9/rerun`. Поле `match` в ответе показывает,
совпал ли sha256 результата с сохранённым.

## Файл .env — необязательный, но полезный

**Сервис полностью запускается без `.env`.** Все основные источники данных (Planetary Computer, Open-Meteo, PANGAEA,
Zenodo) открыты и ключей не требуют.

С `.env` включается одна функция: **дрейф без снимка** (`GET /api/drift`, кнопка «Рассчитать дрейф на 72 ч»
в карточке полевого события). Она показывает, куда течения, волны и ветер унесли бы мусор от места полевого
измерения. Снимок для этого не нужен: поля берутся из реанализов Copernicus Marine, поэтому расчёт работает и для
событий 2014–2016 гг. в Тихом океане, Саргассовом и Северном морях, над которыми снимков Sentinel-2 нет. Open-Meteo
для этих лет не подходит, его течения начинаются только с 2022 г. Без учётных данных эта ручка отвечает `503`,
остальное работает.

Как включить (займёт пару минут):

1. Зарегистрируйте бесплатный аккаунт: https://data.marine.copernicus.eu/register
2. Скопируйте образец: `cp .env.example .env` (Windows: `copy .env.example .env`).
3. Впишите логин и пароль:

```dotenv
COPERNICUSMARINE_SERVICE_USERNAME=ваш_логин_или_email
COPERNICUSMARINE_SERVICE_PASSWORD=ваш_пароль
```

4. Перезапустите сервис.

| Переменная | Зачем | Если не задана |
|---|---|---|
| `COPERNICUSMARINE_SERVICE_USERNAME`, `COPERNICUSMARINE_SERVICE_PASSWORD` | дрейф без снимка по реанализам Copernicus Marine | `GET /api/drift` отвечает 503 |
| `AQUAFLOW_CACHE` | отдельный каталог кеша, если `data/` доступна только для чтения | кеш пишется в `data/` (в Docker — `/app/cache`) |

Файл `.env` не попадает в git. Его читают и сервис ([pipeline/config.py](pipeline/config.py)), и `docker compose`.
Переменные, уже заданные в окружении, важнее значений из файла. Вместо `.env` локально можно один раз выполнить
`copernicusmarine login`.

### Как проходят данные

```
Полевой реестр ──► field.py (отбор, C = N/A) ──► splits.py ──► concentration.py (модели A и B) ──► fusion.py
                                  │
                                  └──► pairs.py ◄── STAC Planetary Computer + ERA5 (реестр пар «событие ↔ снимок»)

Sentinel-2 L2A ──► s2.py ──► features.py ──► XGBoost + фильтры (detect.py) ──► aggregate.py
                                                                                 │ зоны, маска качества,
                                                                                 │ гексы H3, статусы, концентрация
Open-Meteo (течения SMOC, ветер ERA5) ──► drift.py / route.py                    ▼
Copernicus Marine (реанализы)          ──► cmems.py ──► drift.py      backend (FastAPI) ──► frontend (React, MapLibre)
```

## Модели и почему именно они

В сервисе три обученные модели. Детектор и модели концентрации друг от друга **не зависят**. Подробности, формулы
и все метрики — [docs/models.md](docs/models.md).

| Модель | Что отвечает | Метрика | Базовый алгоритм |
|---|---|---|---|
| **Детектор** — XGBoost + фильтры | где на снимке вероятны скопления мусора | MARIDA test: **F1 0,80** (95% ДИ 0,72–0,88), IoU 0,67 | пороги FDI и NDVI: F1 0,02 |
| **Профиль A** — отрицательно-биномиальная GLM | шт./км² пластика ≳2 см | CV MAE **30,4** шт./км² | медиана: 37,1 |
| **Профиль B** — ридж-регрессия по log C | шт./км² мусора ≳2,5 см | CV MAE **173** шт./км² | медиана: 208 |

### Детектор: XGBoost по пикселям

Для каждого пикселя 10 м модель выдаёт вероятность одной из шести групп: мусор, органика (саргассум и др.), суда,
облака, вода, пена и волны. На вход идут 20 признаков: 11 каналов Sentinel-2 после нормализации фона, спектральные
индексы (FDI, NDVI, PI, FAI, NDWI, NDMI) и текстура. Поверх модели работают фильтры: тест против пены, требование
соседей, CFAR 5σ, буфер от облаков, отбраковка сцен со штормом и сильным бликом.

Почему выбрали его:

- **Простые спектральные пороги на сложном фоне не работают.** Классический подход с порогами FDI и NDVI даёт
  F1 0,02–0,04: мутная вода и саргассум дают FDI выше, чем сам мусор. Модели нужно отличать мусор от нескольких
  похожих классов фона одновременно, и XGBoost с этим справляется (F1 0,80).
- **Разметка MARIDA точечная:** размечены отдельные пиксели, а не сплошные маски. Попиксельный классификатор
  использует каждый размеченный пиксель как пример, неразмеченные просто пропускаются.
- **Признаки физически осмысленны,** и видно, на что опирается модель: самые важные — PI (23%), NDVI (13%)
  и текстура FDI (8%).
- **Быстрый и нетребовательный.** Инференс идёт на CPU, GPU только ускоряет обучение.
- **Фильтры повышают точность:** вдвое меньше ложных срабатываний (P 0,66 → 0,78) ценой 8% попаданий.

Нормализация фона (вычитание локального спектра чистой воды) снимает блик, дымку и разницу атмосферной коррекции
между нашими снимками (Sen2Cor) и MARIDA (ACOLITE). Один и тот же код признаков работает при обучении и в сервисе.

**Почему детектор обучен только на MARIDA.** На новых сценах MADOS он часто принимает за мусор морскую слизь (45%
пикселей) и медуз (38%). Мы пробовали три варианта дообучения на MADOS. Лучший поднимает F1 на MADOS до 0,58, но
теряет длинные полосы мусора, а на наших снимках ловит цветение и плёнки. Выбрать вариант можно только по разметке
наших вод, поэтому модель сервиса осталась прежней, а MADOS используется как проверочный набор
([docs/mados.md](docs/mados.md)).

### Модели концентрации: простые модели по полевым данным

Почему концентрация считается по полевым данным, а не по снимку: на 9 парах «полевое событие ↔ снимок в тот же день»
связи между детекциями и плотностью мусора нет (ρ = −0,23, p = 0,56). Рассеянный мусор со спутника не виден.

Почему модели такие простые:

- **Данных мало:** 63 события для A и 33 для B. Сложная модель на таком объёме переобучится, поэтому в моделях
  1–2 признака. Набор признаков выбирается по MAE на групповой кросс-валидации из заранее заданных кандидатов,
  отложенная выборка в выборе не участвует. Каждую модель сравниваем с медианой и IDW (интерполяцией по соседям).
- **Профиль A — отрицательно-биномиальная GLM.** У S2 для каждого события известны число предметов N и площадь A,
  поэтому моделируем само число предметов со смещением log(A). Так счётный шум учитывается честно, а сверхдисперсия
  (α = 0,26) не занижает интервалы. Признаки — только координаты.
- **Профиль B — ридж-регрессия log(C + 1).** У S4 есть только опубликованная плотность, без N и A, поэтому
  моделируем сразу C. L2-регуляризация держит модель устойчивой на 26 обучающих событиях. Признак — расстояние до
  берега: вдвое дальше от берега — примерно в 0,78 раза меньше мусора.
- **Интервалы и статусы.** Интервалы сплит-конформные, по остаткам вне фолдов. Статус «исследовательская оценка»
  ставится, если ближайшее измерение дальше 60 км, такого месяца не было в обучении или признаки вне диапазона
  обучения.
- **Сведение с измерениями.** Рядом с полевыми измерениями оценка модели поправляется регрессионным кригингом
  остатков: чем ближе и свежее измерение, тем больше его вес ([pipeline/fusion.py](pipeline/fusion.py)).

На отложенной выборке профиля B (7 событий) модель уступает медиане. Данных мало, и мы не подгоняли модель под
отложенную выборку. Все цифры — в [docs/summary.md](docs/summary.md).

Не обучаются: пороги фильтров детектора ([configs/detector.yaml](configs/detector.yaml)), полевая концентрация
C = N / A (прямой расчёт) и прогноз дрейфа (физический лагранжев ансамбль по течениям и ветру).

## Воспроизведение результатов

Все параметры заданы в [configs/](configs/). Шаги ниже работают на данных из репозитория. Исключения: шаг
детектора требует MARIDA, проверка на MADOS требует MADOS.

```bash
python -m pipeline.reproduce            # сквозной пересчёт метрик (~5 мин); --offline — без сети
python -m pytest -q                     # тесты: формулы, утечки данных, устойчивость, API

# Разбор конкретного расчёта без изменения кода
python -m pipeline.field explain S2:MSM41_litter-T4
python -m pipeline.concentration explain B 39.72 43.55 2025-07-18T08:10
```

Полный пересчёт с нуля (снимки ~17 ГБ, детекция ~45 мин на GPU, 16 ГБ RAM):

```bash
# MARIDA: https://zenodo.org/records/5151941 → распаковать в data/raw/marida
```

## Ограничения

- При 10 м видны скопления и полосы мусора (от ~20–30% пикселя), а не отдельные предметы.
- Для побережья РФ полевых измерений нет: там профиль B даёт только исследовательскую оценку. Для пресных водоёмов
  концентрация недоступна.
- Пластик, плавник и водоросли спектрально разделяются не полностью. Подтверждение — судно или дрон.
- Детектор обучен на MARIDA (в основном тропики). На регионе, исключённом из обучения, F1 падает в среднем до 0,52.
  Локальной разметки для Чёрного моря пока нет, набор для неё подготовлен: `python -m pipeline.review sample`.
- Течения SMOC (1/12°) не разрешают мелкие бухты. Прогноз дрейфа на парах соседних снимков пока не лучше
  предположения «пятно осталось на месте», поэтому он справочный.
